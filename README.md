# נוכחות מועדון — מערכת נוכחות למאמנים ולניהול

אפליקציית ווב (PWA) של מועדון טניס שולחן מבואות החרמון למעקב נוכחות בקבוצות, ניהול מאמנים והרשאות, ספר טלפונים ודוחות.

כתובת חיה: **https://shahar1987.github.io/ttc-mvh-attendance/**

## מה האפליקציה עושה

- **מילוי נוכחות** — מאמן בוחר קבוצה ותאריך ומסמן נוכחים/נעדרים לכל שחקן; זו המסך היחיד שגם מאמן (לא מנהל) רואה.
- **דשבורד** (למנהלים) — תמונת מצב כללית של המועדון.
- **ניהול קבוצות** — יצירה ועריכה של קבוצות אימון, שיוך שחקנים ומאמנים לכל קבוצה, הגדרת ילדים ונוער / מבוגרים וימי אימון.
- **ספר טלפונים** — רשימת אנשי קשר של שחקני המועדון לחיפוש מהיר.
- **דוחות** — סיכומי נוכחות לאורך זמן לפי קבוצה/שחקן.
- **ניהול הרשאות** — קביעת משתמשים כמנהל (Admin) או כמאמן (Coach); מאמן רואה רק מסך מילוי נוכחות, מנהל רואה את כל התפריט.
- **ייבוא שחקנים** — ייבוא/סנכרון רשימת השחקנים אל אוסף `players` המשותף ב-Firestore.
- **קישור לאפליקציית התחרויות** — פריט תפריט "תחרויות" (למנהלים) שפותח בטאב חדש את אפליקציית ניהול התחרויות של המועדון (`ttc-mvh-tournaments`); בזכות שימוש באותו פרויקט Firebase והתחברות כבר קיימת, המשתמש נכנס ישירות בלי להתחבר שוב.
- **התקנה כ-PWA** — ניתן להתקין למסך הבית (מניפסט + Service Worker), עובד גם באופליין לנתונים שכבר נטענו.

## התחברות והרשאות

התחברות באמצעות Firebase Auth (Email/Password). לכל משתמש יש תפקיד באוסף `users`: **מנהל** (גישה מלאה לכל המסכים) או **מאמן** (גישה למסך מילוי נוכחות בלבד, מוגבל לקבוצות שהוקצו לו).

## טכנולוגיה

React (ללא JSX בקוד המקור — `React.createElement` ישירות), בנוי משני קבצי מקור שמתחברים בזמן ה-build:

- `part-a.js` — imports, קונפיגורציית Firebase, hooks ורכיבי עזר.
- `part-b.js` — רכיבי המסכים (דשבורד, נוכחות, קבוצות, דוחות, הרשאות, ספר טלפונים, תפריט הצד וכו').

### תהליך הבנייה (GitHub Actions, `.github/workflows/deploy.yml`)

בכל push ל-`main`:

1. התקנת תלויות: `react`, `react-dom`, `lucide-react`, `firebase`, `esbuild`, `sharp`.
2. איחוד `part-a.js` + `part-b.js` ל-`bundle.js`.
3. Bundling עם `esbuild` (ESM, minified) ל-`site/app.js`.
4. יצירת אייקוני PWA (192/512/maskable) מתוך `logo.png` באמצעות `sharp`.
5. הרכבת `site/index.html` עם cache-busting (`app.js?v=<sha>`).
6. בדיקות תקינות (גודל bundle, אין `import` גולמי של react).
7. **בדיקת עשן** אוטומטית בדפדפן אמיתי (Playwright) — מוודאת שאין שגיאות עמוד, שהמסך אינו ריק, שמסך ההתחברות מוצג ושהכיוון RTL תקין.
8. פריסה ל-GitHub Pages (`actions/deploy-pages`).

**אין לערוך את `app.js` או את `bundle.js` ישירות** — הם נוצרים אוטומטית מ-`part-a.js`/`part-b.js` בכל build.

### Firebase

אותו פרויקט Firebase של אפליקציית התחרויות (`ttcmh-2a752`) — Auth משותף (כניסה אחת לשתי האפליקציות מאותו דומיין `shahar1987.github.io`) ו-Firestore עם האוספים:

```
players       — רשימת שחקני המועדון (משותף גם לאפליקציית התחרויות)
groups        — קבוצות אימון ושיוך שחקנים/מאמנים
attendance    — רשומות נוכחות לפי קבוצה ותאריך
users         — משתמשי המערכת ותפקידיהם (מנהל/מאמן)
```

## פריסה

1. ריפו ציבורי `ttc-mvh-attendance`, ענף `main`.
2. Settings → Pages → Source: GitHub Actions.
3. כל push ל-`main` מפעיל את ה-workflow שבונה ומפרסם אוטומטית — אין צורך בפעולה ידנית.

## קבצים בריפו

| קובץ/תיקייה | תפקיד |
|---|---|
| `part-a.js` | imports, קונפיגורציית Firebase, hooks ורכיבי עזר |
| `part-b.js` | רכיבי המסכים והתפריט |
| `index.html` | תבנית הדף (טעינת `app.js`, מניפסט, Service Worker) |
| `manifest.json` | הגדרות PWA (שם, צבעים, אייקונים) |
| `sw.js` | Service Worker לתמיכה באופליין ובהתקנה |
| `logo.png` | לוגו המועדון — מקור ליצירת אייקוני ה-PWA |
| `icon.svg` | אייקון גיבוי |
| `.github/workflows/deploy.yml` | תהליך הבנייה, הבדיקות והפריסה האוטומטי |

`bundle.js` ו-`app.js` הם קבצים גזורים (build output) ואינם צריכים להיערך ידנית.
